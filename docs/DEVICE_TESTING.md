# 實機驗收步驟

以下驗收項目必須在實機上進行（模擬器沒有真實的音訊硬體、路由與來電）。結果與截圖請放在 `docs/device/`，並更新 README 對應的表格。

## 準備

1. Xcode 開啟 `PitchCoach.xcodeproj`，在 Signing & Capabilities 選擇自己的 Team，Bundle Identifier 改成自己的（例如 `tw.yourname.PitchCoach`）。
2. 實機執行一次並允許麥克風權限。
3. 產生 A4 測試音，放到另一支手機或電腦播放：

   ```sh
   python3 scripts/make-test-tone.py 442 60
   # 產生 build/test-tone-442.wav
   ```

4. 設定頁確認 A4 = 442 Hz；開發用的「顯示延遲資訊」可視需要開啟。

## AC-11 三種音訊路由的讀數一致（±3 cents）

音源手機固定放在 iPhone 麥克風前約 30 cm，音量固定，在同一個安靜房間進行。每種路由各截一張調音器畫面（含 cents 與 Hz）。

| # | 路由 | 步驟 | 截圖檔名 |
|---|---|---|---|
| 1 | 內建麥克風（無耳機） | 不接任何耳機，播放測試音 | `docs/device/route-builtin.png` |
| 2 | 有線耳機 | 接上有線耳機（Lightning／USB-C），開啟持續音（伴奏從耳機出聲），播放測試音 | `docs/device/route-wired.png` |
| 3 | 藍牙耳機（開啟伴奏） | 連上藍牙耳機，開啟持續音與節拍器，播放測試音 | `docs/device/route-bluetooth.png` |

判定：三張截圖的 cents 兩兩相差都在 ±3 以內。三種情況 App 都固定使用內建麥克風收音（設計文件 §3.1），耳機只負責播放伴奏，因此讀數應幾乎相同。

## AC-08 延遲 ≤ 150 ms

### 方法一：內部時間戳（App 內建）

1. 設定 → 開啟「顯示延遲資訊」。
2. 播放測試音 20 秒，記下面板上的 `P50`、`P95`、`硬體輸入`。
3. 估計值 = 硬體輸入 ＋ 分析窗（2048 / 取樣率，48 kHz 為 42.7 ms）＋ 半個 hop（5.3 ms）＋ P95。

### 方法二：外部慢動作錄影（端到端）

1. 用另一支手機以 240 fps 慢動作錄影，畫面同時拍到撥弦（或敲音叉）的動作與 PitchCoach 螢幕。
2. 在剪輯軟體（例如 iMovie）逐格檢視：起點為音軌波形出現的影格，終點為調音器從「—」變成讀數的影格。
3. 每 240 fps 一格 ≈ 4.17 ms。重複 20 次，記錄 P50 與 P95。

## AC-12 練習中模擬中斷

每項都在**長音練習進行中**（剩餘秒數倒數時）觸發，預期結果：App 不當掉、結果頁顯示「中斷：〈原因〉」並保留已完成的秒數、回到調音器後恢復偵測。建議全程螢幕錄影。

| # | 情境 | 觸發方式 | 預期原因文字 |
|---|---|---|---|
| 1 | 來電 | 用另一支手機撥打 FaceTime 語音或電話 | 來電或其他 App 使用音訊 |
| 2 | 鬧鐘 | 時鐘 App 設 1 分鐘倒數計時器，練習中響起 | 來電或其他 App 使用音訊 |
| 3 | 拔有線耳機 | 練習前接上有線耳機，練習中拔除 | 耳機連接或中斷 |
| 4 | 插有線耳機 | 練習中接上有線耳機 | 耳機連接或中斷 |
| 5 | 藍牙耳機斷線 | 練習中關閉藍牙耳機 | 耳機連接或中斷 |
| 6 | 進入背景 | 練習中回到主畫面再回來 | App 進入背景 |

## AC-13 PDF 存到「檔案」

1. 紀錄 → 週報 → 選日期區間 → 產生週報。
2. 分享／儲存到「檔案」→ 選「我的 iPhone」→ 儲存。
3. 打開「檔案」App 確認 PDF 可開啟、中文正常顯示，截圖存為 `docs/device/pdf-in-files.png`。
